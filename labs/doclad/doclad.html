Введение

Shell - это программа, которая связывает пользователя с операционной системой.

Есть два главных семейства: - Bourne shell (sh) и его потомки: bash, zsh - C shell (csh) и его потомки: tcsh

Bash — самый популярный, стоит почти на всех Linux.
Tcsh — улучшенная версия C shell, используется в FreeBSD и старых Unix.

Зачем сравнивать tcsh и bash?

Вы привыкли к bash, но зашли на сервер FreeBSD - а там tcsh.
Или наоборот, работаете в научной лаборатории, где исторически используют tcsh.

Проблема: команды и настройки, которые работают в bash, в tcsh могут вызвать ошибки.

Цель доклада: показать основные отличия в настройке, чтобы избежать путаницы.

Цель и задачи

Цель: понять, чем настройка tcsh отличается от bash, и как переносить свои конфиги из одной оболочки в другую.

Задачи: 1. Посмотреть, какие файлы настроек используют tcsh и bash. 2. Сравнить, как задаются переменные окружения. 3. Разобраться с алиасами и приглашением командной строки. 4. Увидеть разницу в автодополнении. 5. Собрать плюсы и минусы каждой оболочки.

Конфигурационные файлы

Что делаем bash tcsh
Глобальные настройки (все пользователи) /etc/profile, /etc/bash.bashrc /etc/csh.cshrc, /etc/csh.login
Личные настройки (каждый раз при входе) ~/.bashrc ~/.tcshrc (или ~/.cshrc)
Личные настройки (только при логине) ~/.bash_profile или ~/.profile ~/.login
При выходе ~/.bash_logout ~/.logout

В tcsh разделение удобнее: .tcshrc — для алиасов и поведения, .login — для переменных окружения.

Переменные окружения

Действие bash tcsh
Создать локальную переменную name="Misha" set name = "Misha"
Создать глобальную переменную (доступна везде) export name="Misha" setenv name "Misha"
Добавить папку в PATH export PATH=$PATH:~/bin setenv PATH $PATH:~/bin

Алиасы (короткие имена для команд)

bash tcsh
alias ll='ls -la' alias ll 'ls -la' (пробел вместо =)
Для команд с аргументами нужна функция Можно использовать \!*

Автодополнение (Tab)

Возможность bash tcsh
Дополнение команд Только имена файлов, надо ставить bash-completion Всё из коробки
Исправление опечаток Нет Есть (set complete = enhance)
Список вариантов Настраивается set autolist

Полезные настройки для tcsh:

set complete = (enhance complete)                        
set correct = cmd

Синтаксис скриптов: главные отличия

Условие

bash:

if [ $days -gt 365 ]; then
    echo "Больше года"
fi

tcsh:

if ( $days > 365 ) then
    echo "Больше года"
endif

Цикл по файлам

bash:

for i in *; do
    echo $i
done

tcsh:

foreach i (*)
    echo $i
end

Плюсы и минусы

bash tcsh
Плюсы Чаще используеться
Огромное сообщество		 Удобное автодополнение из коробки
Исправление опечаток
Логичные файлы настроек
Минусы Автодополнение надо донастраивать Меньше распространён
Синтаксис для скриптов сложнее (легко ошибиться с пробелами)

Пример минимального .tcshrc


set complete = (enhance complete)
set autolist
set correct = cmd

set history = 1000
set savehist = (1000 merge)

alias ll 'ls -la'
alias h  'history'

setenv PATH $PATH:~/bin

set prompt = '%B%n@%m%b:%~ %# '

Выводы

  1. Главные отличия tcsh от bash — в синтаксисе:

    • setenv вместо export (и без =)
    • пробелы имеют значение
    • промпт через %, а не \u
    • автодополнение работает сразу

  2. Для интерактивной работы tcsh удобнее благодаря встроенным фичам.

  3. Для скриптов лучше использовать bash — он понятнее и переносимее.

  4. Зная таблицы соответствия, вы легко перейдёте с одной оболочки на другую.
