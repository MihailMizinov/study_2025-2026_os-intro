## 1. Введение

**Командная оболочка (shell)** — это программа, которая обеспечивает интерфейс между пользователем и операционной системой. Пользователь вводит команды, оболочка интерпретирует их и запускает соответствующие программы. Существует два основных семейства оболочек в UNIX-подобных системах:

- **Bourne shell** и его потомки: sh, bash, zsh, ksh;
- **C shell** и его потомки: csh, tcsh.

**Bash** (Bourne Again SHell) — наиболее распространённая оболочка, стандарт в Linux. **Tcsh** (TENEX C shell) — улучшенная версия C shell, созданная Биллом Джоем. Tcsh является оболочкой по умолчанию в FreeBSD и часто встречается в академических и научных средах [1].

При переходе между разными UNIX-системами пользователи сталкиваются с тем, что привычные настройки могут не работать. Это особенно заметно в конфигурационных файлах: синтаксис переменных, алиасов, приглашения командной строки различается. Цель доклада — систематизировать эти различия и предложить практические рекомендации по настройке tcsh для тех, кто привык к bash.

## 3. Конфигурационные файлы

Настройки оболочки хранятся в файлах, которые загружаются при запуске. В таблице 1 приведено соответствие между основными конфигурационными файлами bash и tcsh.

**Таблица 1 — Конфигурационные файлы bash и tcsh**

| Назначение | bash | tcsh |
|:---|:---|:---|
| Глобальные настройки для всех пользователей | `/etc/profile`, `/etc/bash.bashrc` | `/etc/csh.cshrc`, `/etc/csh.login` |
| Личные настройки для интерактивной сессии | `~/.bashrc` | `~/.tcshrc` (или `~/.cshrc`) |
| Личные настройки для сессии входа | `~/.bash_profile`, `~/.profile` | `~/.login` |
| Действия при завершении сессии | `~/.bash_logout` | `~/.logout` |

Как видно из таблицы 1, tcsh различает файлы, выполняемые при каждом запуске терминала (`.tcshrc`), и файлы, выполняемые только при входе в систему (`.login`). Это позволяет логически разделить настройки: в `.tcshrc` удобно помещать алиасы и параметры поведения, а в `.login` — переменные окружения.

## 4. Переменные окружения

Переменные окружения хранят информацию о среде (например, пути поиска исполняемых файлов, домашний каталог). Синтаксис их создания и экспорта различается (таблица 2).

**Таблица 2 — Синтаксис работы с переменными окружения**

| Операция | bash | tcsh |
|:---|:---|:---|
| Локальная переменная | `name="value"` | `set name = "value"` |
| Экспорт переменной в окружение | `export name="value"` | `setenv name "value"` |
| Добавление каталога в PATH | `export PATH=$PATH:~/bin` | `setenv PATH $PATH:~/bin` |

Критическое различие: в tcsh команда `setenv` **не использует знак равенства**. Например, запись `setenv PATH /usr/bin` верна, а `setenv PATH=/usr/bin` вызовет ошибку. Также важны пробелы: в конструкции `set name = "value"` пробелы вокруг знака равенства обязательны. Если их опустить (`set name="value"`), присваивание не будет выполнено корректно.

## 5. Алиасы

Алиасы позволяют создавать короткие имена для часто используемых команд. Сравнение синтаксиса приведено в таблице 3.

**Таблица 3 — Синтаксис алиасов**

| Тип алиаса | bash | tcsh |
|:---|:---|:---|
| Простой алиас | `alias ll='ls -la'` | `alias ll 'ls -la'` |
| Алиас с аргументами | Требуется функция, например: `ll() { ls -la "$@"; }` | Встроенная поддержка через `\!*`<br>`alias findbig 'find . -name "\!*" -size +100M'` |

В tcsh символ `\!*` означает «все аргументы, переданные алиасу». Это позволяет создавать компактные алиасы без необходимости писать отдельные функции.

---

## 6. Приглашение командной строки (prompt)

Приглашение командной строки — строка, отображаемая перед вводом команды. Она настраивается с помощью специальных последовательностей. Сравнение форматов приведено в таблице 4.

**Таблица 4 — Настройка приглашения**

| Элемент | bash | tcsh |
|:---|:---|:---|
| Спецификаторы | `\u` — пользователь, `\h` — хост, `\w` — путь | `%n` — пользователь, `%m` — хост, `%~` — путь |
| Простой промпт | `PS1='\u@\h:\w\$ '` | `set prompt = '%n@%m:%~ %# '` |
| Цветной промпт (зелёный жирный) | `PS1='\[\e[32m\]\u@\h\[\e[0m\]:\w\$ '` | `set prompt = '%B%{\e[32m%}%n@%m%{\e[0m%}%b:%~ %# '` |

В tcsh используются форматные спецификаторы с символом `%`, а также встроенные возможности для изменения стиля: `%B` и `%b` включают и выключают жирное начертание. Цвет задаётся вставкой ANSI-кодов в конструкцию `%{...%}`.

## 7. Автодополнение и история команд

Интерактивные возможности, такие как автодополнение по Tab и поиск по истории, существенно влияют на удобство работы. В таблице 5 сравниваются основные функции.

**Таблица 5 — Функции автодополнения и истории**

| Функция | bash | tcsh |
|:---|:---|:---|
| Автодополнение команд | Только имена файлов; для дополнения команд требуется установка пакета `bash-completion` | Полноценное из коробки |
| Исправление опечаток | Отсутствует | `set complete = enhance` |
| Список вариантов при двойном Tab | Настраивается через `bind` | `set autolist` |
| Поиск по истории | Ctrl+R | Ctrl+R |

Для tcsh рекомендуется включать расширенные возможности с помощью следующих строк в `.tcshrc`:

```tcsh
set complete = (enhance complete)   # умное дополнение с учётом регистра
set autolist                         # показывать список вариантов при двойном Tab
set correct = cmd                     # исправлять опечатки в командах
```

## 8. Синтаксис скриптов: основные отличия

Хотя tcsh ориентирован на интерактивную работу, он также может использоваться для написания скриптов. Синтаксис существенно отличается от bash (таблица 6).

**Таблица 6 — Сравнение синтаксиса скриптов**

| Конструкция | bash | tcsh |
|:---|:---|:---|
| Условный оператор | `if [ условие ]; then ... fi` | `if ( условие ) then ... endif` |
| Цикл по файлам | `for i in *; do ... done` | `foreach i (*) ... end` |
| Множественное ветвление | `case ... esac` | `switch ... endsw` |
| Арифметика | `$((...))` или `expr` | `@` (например, `@ i += 2`) |

Пример условного оператора в bash:
```bash
if [ $days -gt 365 ]; then
    echo "Больше года"
fi
```
Аналогичный код в tcsh:
```tcsh
if ( $days > 365 ) then
    echo "Больше года"
endif
```

## 9. Плюсы и минусы

На основе проведённого сравнения можно выделить сильные и слабые стороны каждой оболочки (таблица 7).

**Таблица 7 — Плюсы и минусы bash и tcsh**

| | bash | tcsh |
|:---|:---|:---|
| **Плюсы** | • Стандарт для скриптов (POSIX-совместимость)<br>• Повсеместное распространение<br>• Огромное сообщество | • Мощное автодополнение «из коробки»<br>• Исправление опечаток в командах<br>• Логичная структура конфигурационных файлов |
| **Минусы** | • Автодополнение требует дополнительной настройки<br>• Разделение `.bashrc` и `.profile` часто вызывает путаницу | • Меньшее распространение<br>• Синтаксис для скриптов менее дружелюбен (чувствительность к пробелам) |

## 10. Пример минимальной конфигурации `.tcshrc`

Для быстрого старта в tcsh можно использовать следующий файл `~/.tcshrc`, который включает основные улучшения и привычные алиасы.

```tcsh
# ~/.tcshrc — базовая конфигурация

# Умное автодополнение и коррекция
set complete = (enhance complete)
set autolist
set correct = cmd

# История команд
set history = 1000
set savehist = (1000 merge)

# Алиасы
alias ll 'ls -la'
alias h  'history'

# Путь к пользовательским скриптам
setenv PATH $PATH:~/bin

# Приглашение: зелёный жирный шрифт
set prompt = '%B%{\e[32m%}%n@%m%{\e[0m%}%b:%~ %# '
```

Этот файл можно скопировать в домашний каталог, после чего при каждом запуске терминала настройки будут применяться автоматически.

## 11. Выводы

1. **Основные отличия** tcsh от bash проявляются в синтаксисе:
   - использование `setenv` вместо `export` (и отсутствие знака `=` в этой команде);
   - обязательные пробелы в конструкции `set name = value`;
   - формат приглашения с `%`-спецификаторами;
   - расширенные возможности автодополнения и исправления опечаток.

2. **Для интерактивной работы** tcsh предоставляет более богатые возможности «из коробки»: интеллектуальное автодополнение, коррекцию команд, логичное разделение конфигурационных файлов.

3. **Для написания скриптов** bash остаётся предпочтительным выбором благодаря POSIX-совместимости и более привычному синтаксису.

4. **Практическая рекомендация:** знание особенностей обеих оболочек необходимо для эффективной работы в гетерогенной UNIX-среде, особенно в научных и образовательных учреждениях, где используются различные операционные системы.
